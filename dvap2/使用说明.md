# dvap2 使用说明

`dvap2` 用来把**已经查出来的主数据**，按外键关系批量补齐成嵌套 JSON，而不用为每一种组合再定义一套互相引用的 struct。

一句话：

> 你先用 GORM 查出一批用户 / 班级 / 订单；再告诉本包「谁挂谁、用哪两个字段对上」；它会自动 `IN` 查询、按关系树组装，最后给你一棵可直接返回给前端的对象树。

和手写循环的区别：

| 手写 | dvap2 |
|------|--------|
| 每个父行再查一次子表（N+1） | 先收集全部外键，一次 `IN` 查出子表，再在内存里挂上 |
| 多层嵌套要写很多组装代码 | 用 `student.class`、`teachers.user.candies` 声明关系网 |
| 不同接口要定义不同 DTO | 结果是动态 map/数组，结构由关系名决定 |

依赖：`gorm.io/gorm`、本仓库的 `bmap`（动态 JSON 树）、`gslicer`（分批/并发）。

```go
import "github.com/k-kkong/dataschema/dvap2"
```

## 1. 这个包有什么

按使用频率：

| 模块 | 干什么 |
|------|--------|
| **RelationLoader** | 核心。声明关系网，从数据库拉取并组装嵌套结果 |
| **Dataer** | 不查库，把两份已经在内存里的数据按条件 HasOne / HasMany |
| **Slicer** | 泛型切片：查找、分页、排序、去重、集合运算 |
| **DataUnit** | 按 `"a.0.b"` 这种路径读写任意 map/slice |
| **Ptr / 时间 / 反射工具** | 指针、日期校验、结构体切片过滤合并等 |

日常业务 90% 的时间只需要 `RelationLoader`。

## 2. 30 秒上手：RelationLoader

假设已有表：`user`、`student`、`class`、`teacher`。

```go
var users []TblUser
db.Find(&users)

rl := dvap2.NewRelationLoader(users, true) // true = 出错时打印堆栈
rl.AddRelation(dvap2.HAS_ONE,  "student",         "id",       "user_id", TblStudent{}, nil, nil)
rl.AddRelation(dvap2.HAS_ONE,  "student.class",   "class_id", "id",      TblClass{},   nil, nil)
rl.AddRelation(dvap2.HAS_MANY, "teachers",        "id",       "user_id", TblTeacher{}, nil, nil)
rl.AddRelation(dvap2.HAS_ONE,  "teachers.class",  "class_id", "id",      TblClass{},   nil, nil)

result := rl.LoadResult(db).GetResult()
if err := rl.Error(); err != nil {
    return err
}
fmt.Println(dvap2.VtoJsonString(result))
```

输入可以是**切片**，也可以是**单个对象**（`var user TblUser`），组装逻辑相同。

得到类似：

```json
[
  {
    "id": 1,
    "name": "花无缺",
    "student": {
      "id": 1,
      "user_id": 1,
      "class_id": "1",
      "class": { "id": 1, "name": "终极一班" }
    },
    "teachers": []
  }
]
```

`AddRelation` 参数含义：

```text
AddRelation(
    关系类型,          // HAS_ONE / HAS_MANY
    关系名,            // 结果里出现的字段路径，用 "." 表示挂到上一层关系下
    fakey,             // 父数据上的字段（当前这一层）
    sukey,             // 子表上的字段
    子表 Model,        // gorm 结构体零值，如 TblStudent{}
    compareFunc,       // 可选，自定义怎么把父子对上；nil 则 fakey == sukey
    cdb,               // 可选，自定义子查询（额外 Where）；nil 则 db.Model(子表)
    subModifyFunc...,  // 可选，挂上的时候改父/子字段
)
```

默认匹配规则（`compareFunc == nil` 时）：

```text
父.Get(fakey).String() != ""  且  等于  子.Get(sukey).String()
```

数字 `1` 和字符串 `"1"` 都能对上，因为比较的是字符串形式。父字段为空则不匹配。

## 3. 关系类型与关系名

### 3.1 HAS_ONE / HAS_MANY

- `HAS_ONE`：每个父元素挂 **一个** 子对象。多个子行命中时取 **第一条**。没匹配到则挂空对象。
- `HAS_MANY`：每个父元素挂 **一个子数组**。可以挂 0 个或多个。
- `BELONG_TO`：常量已定义，当前 `LoadResult` **不会组装**，不要用。

### 3.2 点号 `.`：关系树（必须先声明上层）

```text
student              → 挂在根上
student.class        → 挂在 student 下面（必须先有 student）
teachers.user.candies.candy
```

后一层的 `fakey` / `sukey` 是 **上一层子数据** 的字段，不是根的字段。

例如 `student.class`：`fakey=class_id` 来自 student，`sukey=id` 来自 class。

先声明 `student.class` 再声明 `student` 会 panic：`欲设置的前置关系[student]不存在`。

### 3.3 竖线 `|`：走进已经存在的嵌套字段

`.` 是在「关系网」里往下挂新查出来的表。  
`|` 是在 **当前这一层 JSON 里** 先走进已有字段，再在那里挂数据。

```go
// 每个学校已有 leader: { user_id, title }
// 把 user 挂到 leader 里面，而不是学校根上
rl.AddRelation(dvap2.HAS_ONE, "leader|user", "user_id", "id", TblUser{}, nil, nil)

// 班级数组 → 小组数组 → 给每个小组挂成员
rl.AddRelation(dvap2.HAS_MANY, "classes|groups|members", "gid", "gid", TblMember{}, nil, nil)
```

等价语义：

| 关系名 | 实际挖外键 | 挂载位置 |
|--------|------------|----------|
| `leader\|user` | `leader\|user_id` | `leader.user` |
| `classes\|groups\|members` | `classes\|groups\|gid` | 每个 group 的 `members` |

`.` 和 `|` 可以组合理解：`.` 选中关系网节点，`|` 在该节点的 JSON 里继续下钻。多层 `|`、数组套数组、挂到上一跳刚装上的数组上，都可以。完整例子见 `dataer3_test.go` 的 `TestComplexMultiLayerPipeRelations`。

## 4. 高级用法（必读）

### 4.1 自定义子查询 `cdb`

只拉部分子行（科目过滤、状态、软删、租户等）：

```go
rl.AddRelation(
    dvap2.HAS_MANY, "teachers", "id", "class_id", TblTeacher{},
    nil,
    db.Model(&TblTeacher{}).Where("subject IN ?", []string{"化学", "物理"}),
)
```

`cdb != nil` 时 **不会** 再 `Model(child)`，请自己带上 Model / Table。  
条件写在 `cdb` 上，本包仍会追加 `sukey IN (父键列表)`。

### 4.2 连接时改数据 `SubModifyFunc`

签名（dvap2 用的是 `bmap`，不是 gjson）：

```go
type SubModifyFunc func(p, s *bmap.BMap) (*bmap.BMap, *bmap.BMap)
```

`p` 当前父节点，`s` 当前命中的子节点。必须把映射键留下。

```go
countPeople := func(p, s *bmap.BMap) (*bmap.BMap, *bmap.BMap) {
    p.Set("cnt_user", p.Get("cnt_user").Int()+1)
    return p, s
}

rl.AddRelation(dvap2.HAS_MANY, "students", "id", "class_id", TblStudent{}, nil, nil, countPeople)
rl.AddRelation(dvap2.HAS_MANY, "teachers", "id", "class_id", TblTeacher{}, nil, nil, countPeople)
```

常见用途：计数、打标、改字段名、给子对象加计算字段、丢掉敏感字段。

`HAS_MANY` 时 **每命中一个子行就会调用一次**，所以计数是累加的。

位置参数写法里，它是 `AddRelation` 的最后一个可变参数。更稳妥用 Options，见下一节。

### 4.3 自定义匹配 `CompareFunc`

默认等值不够时（多字段、状态过滤、只取部分子行）：

```go
type CompareFun func(p, s *bmap.BMap) bool

rl.AddRelation(dvap2.HAS_MANY, "subjects", "cid", "cid", TblSubject{},
    func(p, s *bmap.BMap) bool {
        if p.Get("cid").String() != s.Get("cid").String() {
            return false
        }
        n := s.Get("name").String()
        return n == "数学" || n == "物理"
    },
    nil,
)
```

**注意：** 一旦设置了 `CompareFunc`，内存连接会走线性扫描，不再走默认的 O(1) 索引。数据量大时尽量把过滤放进 `cdb` 的 SQL，让 `CompareFunc` 保持 `nil`。

### 4.4 `AddRelationWithOptions`（推荐的高级入口）

功能与 `AddRelation` 相同，但可设置 **分批查询**，字段不易写错。

```go
rl.AddRelationWithOptions(
    dvap2.NewRelationOptions().
        SetRelationType(dvap2.HAS_ONE).
        SetRelation("students.user").
        SetFakey("user_id").
        SetSukey("id").
        SetChild(TblUser{}).
        SetCdb(db.Model(&TblUser{}).Where("status = ?", 1)).
        SetCompareFunc(nil).
        SetSubModifyFunc(func(p, s *bmap.BMap) (*bmap.BMap, *bmap.BMap) {
            s.Set("from", "students")
            return p, s
        }),
)

opt := dvap2.NewRelationOptions().
    SetRelationType(dvap2.HAS_MANY).
    SetRelation("orders").
    SetFakey("id").
    SetSukey("user_id").
    SetChild(TblOrder{})
opt.LoadKeysBatchSize = 500 // 父键很多时，IN 分批；非事务下批次会并行
rl.AddRelationWithOptions(opt)
```

`LoadKeysBatchSize` 只有 Options 这条路能设，`AddRelation(...)` 没有这个参数。

### 4.5 同级多关系 + 深层嵌套（一次拉整棵树）

从班级出发：老师（过滤科目）→ 用户 → 糖果；同时学生 → 用户 → 糖果；并统计人数。

```go
rl := dvap2.NewRelationLoader(classes, true)

rl.AddRelation(dvap2.HAS_MANY, "teachers", "id", "class_id", TblTeacher{}, nil,
    db.Model(&TblTeacher{}).Where("subject IN ?", []string{"化学", "物理"}),
    func(p, s *bmap.BMap) (*bmap.BMap, *bmap.BMap) {
        p.Set("cnt_user", p.Get("cnt_user").Int()+1)
        return p, s
    },
)
rl.AddRelation(dvap2.HAS_ONE,  "teachers.user",                 "user_id",  "id",      TblUser{},         nil, nil)
rl.AddRelation(dvap2.HAS_MANY, "teachers.user.candies",         "id",       "user_id", TblUserHasCandy{}, nil, nil)
rl.AddRelation(dvap2.HAS_ONE,  "teachers.user.candies.candy",   "candy_id", "id",      TblCandy{},        nil, nil)

rl.AddRelation(dvap2.HAS_MANY, "students", "id", "class_id", TblStudent{}, nil, nil,
    func(p, s *bmap.BMap) (*bmap.BMap, *bmap.BMap) {
        p.Set("cnt_user", p.Get("cnt_user").Int()+1)
        return p, s
    },
)
rl.AddRelationWithOptions(&dvap2.RelationOptions{
    RelationType: dvap2.HAS_ONE,
    Relation:     "students.user",
    Fakey:        "user_id",
    Sukey:        "id",
    Child:        TblUser{},
})
rl.AddRelation(dvap2.HAS_MANY, "students.user.candies",       "id",       "user_id", TblUserHasCandy{}, nil, nil)
rl.AddRelation(dvap2.HAS_ONE,  "students.user.candies.candy", "candy_id", "id",      TblCandy{},        nil, nil)

result := rl.LoadResult(db).GetResult()
```

加载顺序（内部）：

1. 从当前层收集所有 `fakey`（去重、跳过空值）
2. `WHERE sukey IN ?` 批量查子表（可分批、可并行）
3. 若该关系还有更深层 `Stash`，对子结果递归 1～2
4. 用 HasOne / HasMany 写回当前层

因此深层关系会先把子树装完，再挂到父上。

### 4.6 挂到「上一跳刚装上的数组」上

和 RelationLoader 递归是同一思路，Dataer 也可以手动做：

```go
// 先给每个小组挂 members
NewDataer().SetMeta(meta).SetJoinKeys("gid", "gid").SetSubGroup(members).
    HasMany(meta, "", "classes|groups|members")

// 再给每个 member 挂 badge（走的是刚写进去的 members 数组）
NewDataer().SetMeta(meta).SetJoinKeys("id", "uid").SetSubGroup(badges).
    HasOne(meta, "", "classes|groups|members|badge")
```

### 4.7 重复路径名、空匹配、单对象根

- 路径段可以重复：`a|a|child` 表示走进 `a.a` 再挂 `child`。
- 匹配不上：`HAS_ONE` 仍会写入空节点；`HAS_MANY` 写入空数组 `[]`。
- 空字符串外键会被 `GetKeys` 丢掉，不会进 `IN` 查询。
- 根可以是对象不是数组：`NewRelationLoader(oneUser, true)` 或 Dataer 对单个 map 做 `HasOne(..., "leader|user")`。

### 4.8 错误处理与堆栈

```go
rl := dvap2.NewRelationLoader(input, true) // OpenPrintErrStack
rl.AddRelation(...)
rl.LoadResult(db)
if err := rl.Error(); err != nil {
    // AddRelation / LoadResult 内部 panic 会被接住，写入这里
}
```

第二个参数为 `true` 时，捕获到 panic 会打印 goroutine 堆栈。

### 4.9 结果怎么用

```go
raw := rl.GetResult()                 // any，一般是 []any 或 map[string]any
jsonStr := dvap2.VtoJsonString(raw)

bm := bmap.Parse(raw)
name := bm.Get("0.student.class.name").String()
```

不要假设还能填回原来的 struct 切片；组装过程会把结构转成动态 map/slice。

## 5. Dataer：内存里手动连接

已经有两份数据、不想走 GORM 时用 Dataer。RelationLoader 内部也是调它来挂树。

```go
meta := bmap.Parse(parents)      // 父
sub  := bmap.Parse(children)     // 子

d := dvap2.NewDataer().
    SetMeta(meta).
    SetJoinKeys("id", "user_id"). // 等值关联，走索引（快）
    SetSubGroup(sub)

d.HasOne(meta, "", "child")           // 每个父挂一个 child
// 或
d.HasMany(meta, "", "children")       // 每个父挂 children 数组

result := d.GetResult()
```

### 5.1 `GetKeys`：按路径抽出去重后的键

```go
d := dvap2.NewDataer()
d.GetKeys(meta, "body2|bid")
d.GetKeys(meta, "classes|groups|mentor|user_id")
fmt.Println(d.Keys) // []string，先出现的优先，空值丢弃，自动去重
```

`|` 表示下钻；遇到数组会对每个元素继续挖。

### 5.2 HasOne / HasMany 的路径

第三个参数是挂载路径，同样用 `|`：

```go
HasOne(meta, "", "child")                 // 根上挂 child
HasOne(meta, "", "body2|ext")             // 走进 body2，挂 ext
HasOne(meta, "", "classes|monitor|user")  // 数组 → 对象 → 挂 user
HasMany(meta, "", "classes|groups|members")
```

第二个参数 `this_key` 给递归内部用，外部调用一律传 `""`。

HasOne 多条命中只取第一条；HasMany 全保留。

### 5.3 索引 vs 自定义比较

```go
// 快：按字段等值建 map，O(n+m)
d.SetJoinKeys("id", "user_id")

// 灵活：每对父子跑一次函数；不要同时 SetJoinKeys，否则自定义逻辑被跳过
d.SetCompareFunc(func(p, s *bmap.BMap) bool {
    return p.Get("flag").String() == "keep" &&
        p.Get("id").String() == s.Get("user_id").String()
})
```

RelationLoader 在 `compareFunc == nil` 时会自动 `SetJoinKeys`。

### 5.4 Dataer 上的 SubModify

```go
d.SetSubModifyFunc(func(p, s *bmap.BMap) (*bmap.BMap, *bmap.BMap) {
    p.Set("tagged", true)
    s.Set("extra", 1)
    return p, s
})
```

可与 `SetJoinKeys` 一起用。

链式风格：每次关系用一个新的 `NewDataer()`，共用同一棵 `meta` 连续挂多层。

## 6. Slicer：泛型切片工具

```go
s := dvap2.NewSlicer(items)       // 默认不拷贝，改 slicer 等于改原切片
s := dvap2.NewSlicer(items, true) // 拷贝一份再操作
```

多数方法改的是 **自身** 并返回 `*Slicer[T]`，可以链式调用。内部有锁，可并发调用同一实例。

### 6.1 查找与划分

| 方法 | 作用 |
|------|------|
| `Len()` / `Data()` | 长度、取出底层切片 |
| `Contains(func(T) bool)` | 是否存在符合条件的元素 |
| `InSilce(item, equal)` | 是否包含某元素（自定义相等） |
| `Count(func)` | 符合条件的个数 |
| `Take(func)` | 第一个命中；没有则零值 |
| `Find(func)` | **原地**只保留命中项 |
| `Divide(func)` | 拆成 hit / miss 两个新 Slicer，不改自身 |
| `Remove(func)` | 原地删除命中项 |

### 6.2 增删改位置

| 方法 | 作用 |
|------|------|
| `Append` / `Prepend` | 尾部 / 头部加 |
| `InsertIdx(idx, ...)` | `idx<=0` 头插，`idx>=len` 尾插，否则插到 idx 前 |
| `PopHead` / `PopTail` / `PopIdx` / `PopWhere` | 取出并删除 |
| `RemoveByIdx` | 按索引删 |

### 6.3 分页、排序、打乱

```go
s.Sort(func(a, b Item) bool { return a.Name < b.Name }) // true 表示 a 排在 b 前
s.SortByField(func(v Item) any { return v.ID }, []int{3, 1, 2}) // 按给定 ID 顺序
s.Page(offset, limit)   // 原地切片；offset 过大或 limit<=0 得到空
s.Reverse()
s.Shuffle(seed) / s.Rand(seed)
```

### 6.4 集合运算（keyFun 返回值必须可比较）

```go
s.Unique(func(v T) any { return v.ID }, otherSlice...)           // 去重，可并入其它切片
s.Intersection(keyFun, a, b)                                     // 与所有 ats 的交集
s.Difference(keyFun, other)                                      // 在 s 不在 other
s.SymmetricDifference(keyFun, other)                             // 只在一边出现
```

### 6.5 包级函数

```go
// 映射到另一种类型
out := dvap2.Map(users, func(u User) string { return u.Name })

// 按 key 合并（可变成另一种类型），保持首次出现顺序
merged := dvap2.DuplicateMerge(items,
    func(i Item) any { return i.ID },
    func(i Item, acc Sum) Sum {
        acc.Total += i.Value
        acc.ID = i.ID
        return acc
    },
)

sum := dvap2.Reduce(nums, func(acc, v int) int { return acc + v })
```

## 7. 其它工具函数

### 7.1 指针

```go
p := dvap2.Ptr(3)              // *int
n := dvap2.PtrValue(p)         // 3；p==nil 时返回零值
ps := dvap2.SliceOfPtrs(1, 2)  // []*int
```

### 7.2 时间

```go
t := dvap2.StringToDate("2024-01-02 15:04:05") // 按本地时区拼 time.Time
ok := dvap2.Validate(t)                         // 晚于 1971-01-01
ok = dvap2.ValidateString("2024-01-02 15:04:05")
```

日期部分是 `年-月-日`，不是注释里写的 yyyy-dd-mm。

### 7.3 DataUnit：点路径读写

```go
u := dvap2.NewDataUnit(data)
v := u.Get("items.0.name").Interface()
u.Set("items.0.name", "新名字")
root := u.Interface()
```

路径用 `.`，数组下标写数字。Set 时如有需要会把节点收成 `map[string]any` / `[]any`。

关系组装请优先用 `bmap`，DataUnit 是轻量路径工具。

### 7.4 JSON / gjson 辅助

```go
s := dvap2.VtoJsonString(v)
g := dvap2.VtoJson(v)                    // gjson.Result
g = dvap2.VSetV(g, child, "0.student")   // 按路径 set 再 parse
str := dvap2.VSSetV(jsonStr, child, "0.student")
arr := dvap2.JArrToInterface(gjsonArr)
```

### 7.5 反射切片（旧接口，新代码建议用 Slicer）

```go
dvap2.FilterStructSlice(src, &removed, &kept, func(x T) bool { ... })
dvap2.FilterStructSliceGetFil(src, &kept, func(x T) bool { ... })

out, err := dvap2.UniqueMergeArray(arr,
    func(a T) string { return a.Name },
    func(prev R, cur T) R { ... },
)

ok, err := dvap2.HasValueInSlice(slice, val, func(a, b T) bool { return a == b })
```

## 8. 性能与并发

默认等值连接（没有自定义 `CompareFunc`）会先按子表 `sukey` 建索引再查找，复杂度 **O(父+子)**，避免每个父元素扫一遍子表。

同级关系（例如同时拉 `student` 和 `teachers`）在 **非事务** 下会并行查库，总耗时接近最慢的那条，而不是相加。若 `db` 或某条 `cdb` 处在事务里，自动改回串行，避免抢同一个连接。

`LoadKeysBatchSize > 0` 时按批 `IN` 查询；多批且非事务时并行，结果按原批次顺序拼回去。

建议：

- 能量化到 SQL 的过滤，放 `cdb`，不要放 `CompareFunc`
- 父键成千上万时设 `LoadKeysBatchSize`（如 500～2000，看数据库对 IN 长度的限制）
- 自己循环里不要再对每个父 ID `Find` 一次

## 9. 注意点与常见坑

1. **先加父关系，再加 `parent.child`。** 否则 panic。
2. **`fakey`/`sukey` 是 JSON 字段名**（一般来自 struct 的 `json` tag），不是 Go 字段名。
3. **`cdb` 要自己 `Model`。** 传入非空 `cdb` 时不会自动 `Model(Child)`。
4. **`SubModifyFunc` 不要删掉关联键**，否则后续更深一层对不上。
5. **`CompareFunc` 与索引互斥。** 自定义比较后不再 `SetJoinKeys`。
6. **`|` 和 `.` 不是一回事。** `.` = 关系网层级；`|` = 当前 JSON 往下走。
7. **结果是动态结构**，不要指望 `GetResult()` 还是原来的 `[]TblUser`。
8. **空外键不查库。** 全部父键为空时该关系不会发 SQL，子节点为空。
9. **`HAS_ONE` 一对多时只留第一条**，要全部用 `HAS_MANY`。
10. **Slicer 默认共享原切片。** 怕副作用就 `NewSlicer(arr, true)`。`Find`/`Page`/`Remove` 等会改自身数据。
11. **`BELONG_TO` 未实现组装**，不要指望 LoadResult 处理它。

## 10. API 速查

### RelationLoader

```text
NewRelationLoader(input any, openPrintErrStack bool) *RelationLoader
AddRelation(type, relation, fakey, sukey, child, compare, cdb, modify...) *RelationLoader
AddRelationWithOptions(*RelationOptions) *RelationLoader
LoadResult(db *gorm.DB) *RelationLoader
GetResult() any
GetInput() any
Error() error
```

### RelationOptions

必填：`RelationType` `Relation` `Fakey` `Sukey` `Child`  
可选：`CompareFunc` `Cdb` `SubModifyFunc` `LoadKeysBatchSize`

链式：`SetRelationType` `SetRelation` `SetFakey` `SetSukey` `SetChild` `SetCompareFunc` `SetCdb` `SetSubModifyFunc`  
`LoadKeysBatchSize` 直接给结构体字段赋值。

### Dataer

```text
NewDataer()
SetMeta / SetSubGroup / SetCompareFunc / SetSubModifyFunc / SetJoinKeys
GetKeys(input, "a|b|c")
HasOne(input, "", "a|b|field")
HasMany(input, "", "a|b|field")
GetResult()
```

### 常量

```text
HAS_ONE    一对一（多对一也用这个，每个父只挂一个子）
HAS_MANY   一对多
BELONG_TO  已定义，LoadResult 暂不处理
```
